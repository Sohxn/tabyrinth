# Tabyrinth Sync & License Fixes - Oct 12, 2026

## Completed Changes

### 1. License & Activation (The "Guest Mode" Fix)
- **Unified State**: Moved `isPro` and `licenseKey` from nested `tabTreeData` to the top level of `chrome.storage.local`.
- **UI Persistence**: The side panel now reads the top-level `isPro` flag, preventing the extension from reverting to Guest Mode after the panel is closed/reopened.
- **Corrected Activation**: `activateLicenseKey` now writes to the top-level storage, ensuring immediate and persistent Pro status.

### 2. Sync Reliability (The "Inconsistent" Fix)
- **MV3 Lifecycle Fix**: Moved `bootExtension()` and `setupSyncListeners()` to the top-level of the background worker. The sync engine now initializes every time the service worker wakes up, rather than only on install/startup.
- **Global Locking**: Replaced local promise queues with the **Web Locks API** (`navigator.locks.request`). This prevents race conditions between the background worker and side panel.
- **Persistent Debouncing**: Replaced `setTimeout` with `chrome.alarms` for pushes. Pending syncs now survive service worker suspension.
- **Revision-Based Sync**: Implemented `baseUpdatedAt` timestamps. If the server returns a 409 Conflict, the client now pulls, merges the remote state (preserving live tabs), and re-pushes.
- **Strong Hashing**: Upgraded from a 32-bit fast hash to **SHA-256** to reliably detect state changes.

### 3. Efficiency & Cost Reduction (The "Request Volume" Fix)
- **Content Hashing**: Added a check that compares the current state hash against `syncHash` in storage. Zero requests are sent if the data hasn't changed.
- **Adaptive Batching**: Increased the debounce window to 20 seconds to batch multiple rapid changes into a single request.
- **Event Filtering**: Filtered out "noisy" storage updates (e.g., `lastActiveTabID`, `isLoading` flags) so they don't trigger unnecessary cloud syncs.
- **Worker Heartbeat**: Optimized the Cloudflare Worker to only update the `lastSeen` timestamp if >60s have passed, drastically reducing KV write costs.

### 4. Data Integrity
- **Boot-Wipe Fix**: Moved `syncExistingTabs()` out of the general wake-up path. It no longer calls `resetToActiveTabsOnly()` on every worker wake, preserving ghost nodes and notes.
- **Schema Expansion**: Updated the Worker's Zod schemas to ensure `notes` and `isClosed` flags are not stripped during server-side validation.

## Remaining / Pending Issues

### 1. Pull Verification (High Priority)
- **Current State**: Push is verified as working via logs. Pull is functional but "silent."
- **Next Step**: Verify that remote changes are correctly pulled and merged into the local state during boot and via the 5-minute alarm.

### 2. Tab ID Mapping (Architectural)
- **Current State**: Tab IDs are per-device. Remote tabs are currently merged as "ghosts" to avoid colliding with local live tabs.
- **Future Improvement**: Consider syncing only workspace structure and notes, rather than raw Chrome Tab IDs, for better cross-device consistency.

### 3. KV Atomicity (Edge Case)
- **Current State**: Optimistic locking handles most conflicts, but KV is eventually consistent.
- **Future Improvement**: If high-concurrency conflicts persist, evaluate moving to Cloudflare Durable Objects.

## How to Verify
1. **License**: Activate -> Close Panel -> Open Panel -> Should still be Pro.
2. **Sync**: Make change -> Wait 20s -> Check `wrangler tail` or console for `[SYNC] ok - pushed`.
3. **Persistence**: Add note -> Close tab -> Restart Browser -> Note and Ghost should persist.
4. **Costs**: Rapidly switch tabs -> No requests should be sent to the worker.
